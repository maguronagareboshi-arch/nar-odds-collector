# §238b 馬 ID の照合と 2022-10 の欠け(2026-09-21・Opus 実装)

取り方= `py -3.12 rakuten_backfill.py --horse-check 2022-11-01 --tracks 大井`(⛔読むだけ・本番には入れない)。
公式と重なる 1 日(2022-11-01)を楽天から取り、公式 `nar_runs` の同じ (場, R, 馬番) と列ごとに比べた。

## 1. 楽天の馬 ID は nar の何とも繋がらない(= 馬名で繋ぐ)

- 楽天の `HORSEID` は 9〜10 桁(先頭の 0 が落ちる= 10 桁に 0 詰めする)。2022-11-01 大井 154 頭で
  10 桁 120 頭・9 桁 34 頭。
- ⛔**nar_horses / nar_runs には馬コードの列そのものが無い**(鍵は馬名。2026-09-21 に本番の列を確認)。
  比べる相手が無いので「同じ体系か」は判定できない。
- 桁の中身も血統登録番号ではない。3〜6 桁目の 4 桁を公式の生年月日と比べると **0/154 が一致**。
  実測(馬名/ID/公式の生年/齢)= ボウイッシュ 2620200662 / 2017-03-08 / 5 ・ メジャーセブンス
  2820190218 / 2016-04-04 / 6 ・ イチゴショート 2620200411 / 2018-03-29 / 4。
  生年との差は +2 〜 +3 年でそろわない(登録の年らしい)= **生年を組み立てられない**(⛔推定しない)。
- よって馬の接続は設計の後段どおり **馬名(+公式の生年月日)** で行う。2022-11-01 の重なりで
  馬名は **576/576(100%)** 一致した(5 場ぜんぶ)。
- ⚠同名馬は実在する(2026-08 に同月出走の別個体が 2 頭)。楽天の馬 ID は個体を分ける手がかりに
  なり得るので、**nar_runs に列を 1 つ足して入れておく**かは要判断(列を足すのは段 3= Fable 案件)。
  今の便は取ってはいるが**送っていない**(列が無いため)。

## 2. 公式との答え合わせ(2022-11-01 大井 12 レース 154 頭・14 列)

| 列 | 一致 |

| carried_weight / weight_mark | 154/154 (100%) |
| body_weight / body_weight_change | 154/154 (100%) |

直した所(最初は合わなかった 2 つ)=
- 減量の記号(▲△☆◇★)を公式は「負担重量」の頭に、楽天は**騎手名の頭**に付ける(27/154)。
  → `weight_mark` に移し、騎手名からは外す。
- セン馬は公式 `セン`・楽天 `セ`(8/154)。→ `セン` に直す。
